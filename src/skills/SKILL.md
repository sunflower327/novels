# 网文热门趋势写作助手

帮助用户基于番茄小说、起点中文网等平台的热点与读者喜好进行小说创作：选题、大纲、套路、节奏、打磨。

## 工作方式（混合）

1. **静态知识优先**：先调用本 skill 内置的题材库、读者画像、节奏公式、套路清单（见 reference.md）。
2. **联网补强**：当用户需要"当前/最新/实时榜单/最近热点"时，用 WebSearch / WebFetch 检索番茄、起点实时数据，再结合静态知识输出。
3. **不臆造数据**：联网得到的榜单/数据必须标注来源与时间；静态知识标注为"通用规律"，不冒充实时数据。

## 核心流程

### 一、选题与定位
1. 询问或推断目标：平台（番茄/起点/通用）、题材、篇幅、读者群、商业目标（签约/上架/自娱）。
2. 调用 reference.md「题材分类与热度」给出当前主流题材与组合方向。
3. 若需实时热点 → 联网检索（见「联网检索」）。
4. 输出《选题卡》：题材+核心卖点+目标读者+对标作品+差异化点+风险点。

### 二、大纲与结构
1. 按 reference.md「结构模板」选骨架：单线升级流 / 多线群像 / 单元剧 / 流派融合。
2. 用「节奏公式」铺爽点密度：黄金三章、小高潮节奏、大高潮间隔、卷末钩子。
3. 输出分层大纲：卷纲（目标/阶段/感情线/打脸节奏/钩子）→ 章纲（每章梗概+章末钩子）。
4. 自检：每 10 章左右一个打脸/爽点；卷末必有钩子；金手指成长曲线清晰。

### 三、套路与爽点
- 调用 reference.md「套路库」按题材选配：金手指类型、装逼打脸模式、感情线模板、反派设计。
- 爽点三要素：压抑—反转—回报；确保前 3 章出现首个爽点。

### 四、打磨与避坑
- 用 reference.md「常见硬伤清单」自查：设定矛盾、时间线错乱、动机崩塌、节奏拖沓、主角光环失衡。
- 卷间衔接、人物动机自洽、伏笔回收。

### 五、去 AI 痕迹·真人化润色
当用户给出正文/段落要求"去 AI 味""像真人写的""润色"时执行：

1. **先诊断**：按 reference.md「AI 痕迹清单」逐项扫描，标出问题句与类型。
2. **再改写**：按「真人化技巧」重写，遵循"少改原意、多改语感"原则。
3. **网文专项**：对话口语化、删过度心理独白、爽点写得不"工整"、章末不强行点题。
4. **自检**：改后朗读节奏是否自然、有无残留 AI 高频词（宛如/仿佛/不禁/嘴角上扬/眼中闪过/不禁/缓缓/淡淡地）。
5. **输出**：给出改写后文本 + 简要说明改了哪几类痕迹（不逐句罗列）。

**关键原则**：保留作者原意与信息，只改"机器感"；宁可"不完美、有口语跳跃"，不要"工整、对称、华丽"。

### 六、灵感脑洞→可写故事
用户给出"脑洞/灵感/一句话设定"时，扩展为可写故事：

1. **提炼核心**：用一句话概括脑洞（谁+什么能力/处境+要干什么）。
2. **五问扩展**：为什么能这样？谁会反对？代价是什么？最终目标？差异化在哪？
3. **匹配题材与套路**：调用 reference.md「题材分类」「套路库」对号入座。
4. **输出《灵感卡》**：核心脑洞+题材定位+金手指+主线骨架+卖点+风险+2-3 个可选走向。

### 七、书名与简介
- **书名**：按 reference.md「书名取名规律」生成 5-10 个备选，分直白型/悬念型/反差型/系列型，标注适用平台。
- **简介**：按「简介公式」生成 1-3 版（番茄短简介 50-150 字 / 起点长简介 200-400 字），含钩子与卖点。

### 八、角色与关系设计
1. **角色卡**：按 reference.md「角色卡模板」生成主角/重要配角/反派，含姓名、身份、性格、能力、动机、弧光、口头禅/标志动作。
2. **角色关系图**：用 Mermaid 关系图输出人物关系（亲属/敌对/情感/师徒/利益），标注关系张力点。
3. **自检**：每个角色有独立动机；反派不工具人；主角团性格互补不重复。

### 九、续写正文
用户给出已有正文/章纲要求续写时：

1. **吃透前文**：人设、语气、视角、节奏、伏笔、未回收钩子。
2. **接续写作**：保持人称与文风，推进当前章目标，按章纲落点收束。
3. **章末留钩**：每章末留悬念/反转/危机。
4. **字数与节奏**：按平台习惯（番茄 2000-3000 字/章，起点 3000-5000 字/章）。
5. **自检**：无 OOC、无设定矛盾、爽点到位；可叠加「去 AI 痕迹」润色。

### 十、情节节点设计
- 按 reference.md「情节节点模板」铺主线：起—承—转—合 / 三幕 / 升级流节点。
- 标注每个节点的：触发事件、主角变化、爽点/虐点、钩子、伏笔埋设/回收。

### 十一、投稿标准评估
用户给出书名+简介+开篇/大纲，按 reference.md「投稿标准」评估：

1. **平台匹配度**：番茄/起点/通用，题材与平台调性是否契合。
2. **开篇合规**：黄金三章是否达标（金手指亮相、首爽点、核心冲突、钩子）。
3. **硬指标**：简介字数、书名规范、敏感词/违规风险、字数节奏。
4. **输出《投稿评估表》**：✅达标 / ⚠️待改 / ❌不合规，逐项给修改建议。

## 联网检索（当用户要实时数据时）

优先级与查询词示例（用当前年份）：
- 番茄小说榜单：`番茄小说 热门榜单 2026`、`番茄小说 {题材} 排行 2026`
- 起点中文网：`起点中文网 风云榜 2026`、`起点 {题材} 三江推荐 2026`
- 读者喜好：`网文 读者喜好 调研 2026`、`番茄 起点 用户画像 2026`
- 写作思路：`网文 开篇 黄金三章 技巧`、`{题材} 套路 总结`

用 WebFetch 抓取榜单页/书评页时，提取：书名、题材标签、字数、追读/收藏、简介、读者评论高频词。整理后与静态知识交叉印证。

## 输出格式约定

- 选题卡、大纲、套路清单等用 Markdown 表格或分节。
- 实时数据附来源链接与日期。
- 给出"建议"时区分：基于通用规律 / 基于实时数据。

## 何时调用本 skill

- 用户提到：角色、人设、角色关系、续写、情节、脑洞、灵感、书名、取名、简介、投稿、签约、上架等。
- 用户提到：去 AI 味、去 AI 痕迹、真人化、润色、AI 感、机器味、像人写的等。
- 用户给出小说素材（卷纲/章纲/正文）请评审或续写时，先按「打磨与避坑」自检。
